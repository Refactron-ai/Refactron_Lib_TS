# v0.3 Phase 0 — Real-codebase shortlist

**Goal:** validate the SQLAlchemy migration's premise (§0 of the strategy doc) against actual SQLAlchemy 1.x codebases before building the rewriter.

## Selection criteria

- Uses SQLAlchemy 1.4 (still 1.x; pre-2.0)
- Has a runnable test suite (any framework)
- Open-source, cloneable, installable in a clean Python environment without manual setup

## Trial venue

E2B sandboxes driven from `/tmp/phase0-trial.py`. One sandbox per trial run, 30-min timeout. Refactron's `feat/v0.3-sqlalchemy-phase0` branch is packed (`npm pack`) and `npm install --prefix ~/.npm-global -g`-ed into the sandbox. The CLI is invoked through a small Node driver (`refactron-trial-driver.mjs`) that instantiates `RefactronAnalyzer({ transforms: ['sqlalchemy_query_to_select'] })` so the Task 3 coverage gate fires.

## Codebases trialled

| # | Project | Repo | Branch | Install cmd |
|---|---|---|---|---|
| 1 | flask-appbuilder | github.com/dpgaspar/Flask-AppBuilder | default | `pip install --user -e . pytest coverage` |

|---|---|

## Beta-user outreach

None for this round. The 2-codebase OSS trial yielded clear enough signal to make the G0 call without a private codebase data point. If the call had been on the threshold edge, this would be the next move.

## Re-trial conditions

This Phase 0 trial is the v1 cut. Re-run when:

- The detector grows the `Model.query.filter(...)` pattern (currently a blind spot — see G0 report)
- We get a beta user willing to share a 1.x codebase with a real test suite
- The flagship pivots and a different corpus becomes relevant
