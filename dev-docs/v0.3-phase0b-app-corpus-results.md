# v0.3 Phase 0b — G0 re-run on application corpora

**Runs:** 2026-07-01, E2B sandboxes (node v20.9.0 / Python 3.11.6)
**Refactron under test:** `feat/v0.3-preflight-safety-report` HEAD (`1e48d9a`) — the `preflight` pipeline, run via `driver.mjs` (analyzer + `buildSafetyReport`, auth-gate bypassed).
**Question:** the 2026-06-19 G0 STOP (0/227 covered) was measured on *libraries*. Do real SQLAlchemy 1.x **applications** with real test suites have enough test-covered, safe-to-rewrite query sites to justify building an auto-rewriter?

## Verdict: INCONCLUSIVE after 3 attempts. Empirical G0-on-apps is impractical via ephemeral OSS sandboxing; recommend closing on the meta-finding.

No run has produced a valid safe/unproven ratio from a large, well-tested 1.x corpus. This is a corpus/tooling-budget problem, not a tool defect — the detector and coverage pipeline are validated (below). After three attempts the practical conclusion is that a definitive ratio requires a **beta-user codebase**, not more OSS-sandbox iterations.

## What IS validated (the runs were not wasted)

1. **The detector works on real apps.** flaskbb: **298** genuine 1.x query sites found across `views.py`/`models.py`/`services/`, with a sensible flag breakdown (bulk-delete-semantics, joinedload-needs-unique). cosmicpython: correctly flagged both `session.query(...)` sites as multi-column-select.
2. **Coverage tagging is genuinely correct end-to-end.** cosmicpython is the proof: `repository.py:49` → `testCovered: yes` (its test exercises that query), `repository.py:53` → `no`. The walk → detect → `coverage run -m pytest` → verdict chain produces real per-site coverage on a real app.
3. **The `unproven` semantics hold** and the hard-gate philosophy is right — invalid runs are (now) excluded, never counted as 0%.

## The blocker, precisely

The one corpus that could answer the question — **CTFd** (large, real, well-tested, 661 tests, 1.4, pervasive `Model.query`) — **timed out** on its coverage run inside the sandbox's per-command ceiling. A full-suite `coverage run -m pytest` over 661 DB-backed tests needs ~15–25 min; the run was capped at 15.

## Harness fixes applied (for a potential attempt 3)

- **Usability now requires `collectable`** — a suite that can't import is excluded (kills the false-STOP path).
- **Per-corpus `driver_timeout`; CTFd raised to 1800s**, sandbox to 3000s.
- **flaskbb install hardened** — explicit `flask-login` + siblings so its suite actually imports.

## Meta-observation (strengthening across attempts)

Across two attempts and six repos, a large, well-tested SQLAlchemy **1.x** application that (a) installs on modern Python, (b) runs its full suite fast enough to measure in a sandbox, and (c) has enough *safe-shape* query sites — has not been obtained. Libraries don't cover their data layer (attempt 0); apps have migrated to 2.0, rotted off modern Python, need Postgres, or are too heavy to run under coverage in budget (attempts 1–2). If clean, measurable 1.x-with-coverage corpora are genuinely this scarce, that itself argues the durable product is the **verification/coverage preflight**, not an auto-rewriter — consistent with the verification-layer strategy. This is now a stronger hypothesis, but still not a closed conclusion.

## Decision (2026-07-01): closed on the meta-finding

After three attempts, **G0-on-applications is closed as inconclusive-by-scarcity**, and the founder accepted the meta-finding:

- **The auto-rewriter stays out of scope.** It is not built until a real customer codebase demonstrates a measurable population of test-covered, safe-to-rewrite 1.x query sites. The inability to even *find* such a corpus across six OSS repos is itself evidence the rewriter's addressable surface is thin.
- **`preflight` (the verification/coverage artifact) is the product** — this is what ships (PR #74). The G0 outcome does not block it.
- **Revisit only with a beta-user codebase.** The fixed, reusable harness is preserved at `dev-docs/g0-harness/` for that day — it is the highest-signal path to a definitive ratio.

This is consistent with the verification-layer strategy (`docs/superpowers/specs/2026-06-26-refactron-verification-trust-layer-strategy.md`), which already positioned the SQLAlchemy migration as a demo of the trust gate, not the product.

**Status:** G0-on-applications CLOSED (inconclusive → rewriter out of scope). Harness preserved at `dev-docs/g0-harness/`.
