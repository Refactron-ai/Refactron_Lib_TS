Cline manages MCP servers from its own panel inside VS Code, backed by a settings file in the extension's storage directory.

## Config location

Open it from the UI: click the **MCP Servers** icon at the top of the Cline pane, then **Configure MCP Servers**. That opens `cline_mcp_settings.json` directly.

| OS      | Path                                                                                                            |
| ------- | --------------------------------------------------------------------------------------------------------------- |
| macOS   | `~/Library/Application Support/Code/User/globalStorage/saoudrizwan.claude-dev/settings/cline_mcp_settings.json` |
| Windows | `%APPDATA%\Code\User\globalStorage\saoudrizwan.claude-dev\settings\cline_mcp_settings.json`                     |
| Linux   | `~/.config/Code/User/globalStorage/saoudrizwan.claude-dev/settings/cline_mcp_settings.json`                     |

Cline stores this separately from VS Code's own `.vscode/mcp.json`. Configuring one does not configure the other.

## Add it

```json
{
  "mcpServers": {
    "refactron": {
      "command": "refactron-mcp",
      "disabled": false,
      "timeout": 900
    }
  }
}
```

`timeout` is in seconds and matters here. Cline defaults to 60, and `verify_change` runs your whole test suite, so a real project will blow past that and Cline will report a failure that is really a timeout. Set it to comfortably more than a full suite run.

To pin the version and skip the global install:

```json
{
  "mcpServers": {
    "refactron": {
      "command": "npx",
      "args": ["-y", "-p", "refactron@0.3.0", "refactron-mcp"],
      "disabled": false,
      "timeout": 900
    }
  }
}
```

The `-p` flag is required. `refactron-mcp` is a second binary of the `refactron` package, not a package of its own.

## Verify the connection

Open the **MCP Servers** panel. `refactron` is listed with a green dot, and expanding it shows one tool: `verify_change`.

## Troubleshooting

- **The server shows red**: expand it in the panel to read the error. `spawn refactron-mcp ENOENT` means the binary is not on `PATH`; use the absolute path from `which refactron-mcp`, or the `npx` form.
- **A verification fails after about a minute on a suite that takes longer**: that is the default `timeout` of 60 seconds, not a verdict. Raise it.
- **Changes do not take effect**: click **Restart** on the server row in the MCP Servers panel.
- **Cline asks for approval on every call**: add `verify_change` to `autoApprove` for the `refactron` server. It only reads your repository and writes to a temporary shadow copy, so approving it once is reasonable.
- **The server is missing after a VS Code update**: reinstalling the extension can reset `cline_mcp_settings.json`. Keep your block somewhere you can paste it back.
